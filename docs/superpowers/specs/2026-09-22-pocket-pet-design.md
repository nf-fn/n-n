# ポケットペット設計仕様

**日付:** 2026-09-22
**対象ハード:** M5Stack AtomS3R
**開発環境:** PlatformIO + M5Unified (C++)

## 1. コンセプト

AtomS3R を手のひらサイズの生き物にする。撫でる・振る・傾ける・叩くといった
触り方に、顔の表情とアニメーションで反応する。

作者自身が持ち歩いて遊ぶためのおもちゃであり、他人に配る製品ではない。

### スコープ

このプロジェクトの成功は「触ったときに生きている感じがするか」の一点で決まる。
反応の質にすべてを注ぐ。

**含むもの**

- IMU による触られ方の検出
- 電源が入っている間だけ連続する短期的な気分
- パラメトリックな顔の描画とアニメーション

**含まないもの（意図的に外す）**

- 電源を切っても残る永続状態。セーブもロードもしない
- 成長・育成・レベル・ステータス
- 歩数計や活動記録
- Wi-Fi、BLE、ネットワーク通信
- 音声（AtomS3R 本体にスピーカーもマイクも無い）
- 地磁気センサ (BMM150) の利用。この遊びには不要

電源投入のたびにペットは同じ初期状態から始まる。これは仕様であって、制限ではない。

### 電源

開発中は USB 給電を前提とする。バッテリ拡張は後で検討するため、常時全力で描画し
続ける前提の設計は避ける（アイドル時にフレームレートを落とす余地を残す）が、
省電力の作り込みは初期スコープに含めない。

## 2. 入力と反応の対応

| 触られ方 | 検出方法 | 反応 |
|---|---|---|
| 傾ける | 重力ベクトルの向き | 目玉が下方向に転がる。顔全体が少し傾く。常時効いている |
| 撫でる | 小振幅・高周期の加速度 | 目を細める、頬が赤らむ、ゆっくり揺れる |
| 振る | 大振幅スパイクの連続 | 目を回す、めまい。続けると怒る |
| 叩く / つつく | 単発の鋭いスパイク | びくっと跳ねる、驚き顔 |
| 持ち上げる | 静止 → Z 軸方向の加速 | はっと目を開けてこちらを見る |
| 逆さにする | 重力 Z が負 | 困り顔、血が上る |
| くるくる回す | ジャイロのヨー角速度 | 目が回転を追う、笑う |
| 放置 | 一定時間の静止 | だんだん退屈 → うとうと → 寝息 |
| 画面を押す | ボタン | 起こす / かまう |

「傾ける」は他のイベントと排他ではなく、常に姿勢として効き続ける。
残りは離散的なイベントとして発火する。

### 気分の連続性

永続状態は持たないが、**電源が入っている間、気分は連続している**。
振られ続ければ怒りが溜まり、撫でれば落ち着く。この短期的な慣性が、
永続状態なしでも手応えを生む中心的な仕掛けである。

## 3. アーキテクチャ

ハードに触る層と、触らない純粋ロジック層を完全に分離する。

おもちゃの面白さの大部分は「撫でるを撫でると判定する閾値」と「気分の遷移カーブ」の
チューニングで決まる。そこを実機への書き込みなしで反復できるかが開発速度を決める。

```
[I/O]  ImuSource       M5.Imu → ImuSample{ax,ay,az,gx,gy,gz,t}
          ↓
[純粋] MotionAnalyzer  ImuSample の列 → Posture + MotionEvent
          ↓
[純粋] Mood            MotionEvent 列 + 経過時間 → MoodState
          ↓
[純粋] FaceComposer    MoodState + Posture → FaceParams
          ↓
[I/O]  FaceRenderer    FaceParams → M5GFX 描画
```

### 各ユニットの責務

**ImuSource** (I/O)
M5Unified の `M5.Imu` から加速度・ジャイロを読み、タイムスタンプ付きの
`ImuSample` を返す。軸の向きの補正もここで吸収し、以降の層には
「画面に対して素直な座標系」だけを見せる。

**MotionAnalyzer** (純粋)
`ImuSample` の列を受け取り、2 種類の出力を出す。

- `Posture` — 連続量。重力ベクトルから得た傾き、上下の向き
- `MotionEvent` — 離散イベント。撫で・叩き・振り・回し・持ち上げ

内部に短いリングバッファを持ち、直近の窓に対する振幅・周期・スパイク判定で
イベントを識別する。M5 のヘッダを include しない。

**Mood** (純粋)
`MotionEvent` の列と経過時間から `MoodState` を更新する。

- `arousal` — 覚醒度。放置で下がり、刺激で上がる
- `valence` — 機嫌の良し悪し
- `dizziness` — めまい。振られると溜まり、時間で抜ける
- `anger` — 怒り。乱暴に扱われ続けると溜まる
- `sleepiness` — 眠気。静止時間で上がる

各値は時間減衰する連続量として持つ。状態機械ではなくパラメータの集合とすることで、
表情の中間表現が自然に出る。

**FaceComposer** (純粋)
`MoodState` と `Posture` から `FaceParams` を組み立てる。
目の位置・開き具合・口の形状・顔の傾き・色。

顔はドット絵スプライトではなく、パラメータで動かす。スプライトを何十枚も描かずに、
傾きに連動した滑らかな中間表現が出せるため。

**FaceRenderer** (I/O)
`FaceParams` を M5GFX で描く。`M5Canvas` に 128×128 を丸ごと描いてから
一括転送し、ちらつきを消す。フレームバッファは 128×128×2 = 32KB で、
8MB の PSRAM に余裕で載る。

### 動作レート

- センサ読み取り: 約 100Hz
- 描画: 30fps

## 4. テスト戦略

PlatformIO の `env:native` を用意し、純粋層 (`MotionAnalyzer` / `Mood` /
`FaceComposer`) を Mac 上で直接コンパイル・テストする。

### モーションフィクスチャ

デバッグビルドで IMU の生データをシリアルへ CSV 出力する経路を用意する。
実際に「撫でる」「振る」「叩く」「ポケットに入れて歩く」を実機で録り、
`test/fixtures/*.csv` に保存する。

以降のテストは、この実データを `MotionAnalyzer` に流し込んで期待するイベントが
出るかを検証する。これにより「撫でたのに叩いたと誤判定する」種の問題を、
実機への書き込みなしで再現・修正できる。

誤判定を見つけるたびにフィクスチャが増え、閾値のチューニングで過去の挙動が
壊れないことが保証される。この仕組みの有無が、この種のプロジェクトの完成度を
決定的に左右する。

`FaceComposer` は入力から出力パラメータへの純粋関数なので、代表的な
`MoodState` に対する `FaceParams` を検証する。描画そのものは目視で確認する。

## 5. 実装の順番

1. **顔が出て、傾けると目玉が転がる**
   `ImuSource` → `Posture` → `FaceComposer` → `FaceRenderer` の縦の串を通す。
   ここまででおもちゃとして既に成立する
2. **叩く・振る・撫でるの検出**
   同時に CSV 出力とフィクスチャ基盤も作る
3. **気分の慣性と表情遷移**
   `Mood` を入れ、反応が連続的になる
4. **放置 → うとうと → 寝息、細かい演出**

## 6. 実機で確認が必要な未確定事項

以下は記憶ベースの情報であり、着手時に実機とライブラリで確認する。

- AtomS3R の RGB LED の有無と駆動方法。あれば感情表現の補助に使う。
  無くても設計は成立する
- 手元の M5Unified が BMI270 に対応したバージョンか。
  非対応なら BMI270 を直接叩くドライバを `ImuSource` 内に閉じ込める
- IMU の軸の向きと画面の向きの対応関係。実測して `ImuSource` で補正する

いずれも `ImuSource` の内部に閉じるため、確認結果がどうであれ上位層の設計は変わらない。
