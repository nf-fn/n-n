# ポケットペット設計仕様

**日付:** 2026-09-22
**対象ハード:** M5Stack AtomS3R
**開発環境:** PlatformIO + M5Unified (C++)

## 1. コンセプト

AtomS3R を手のひらサイズの生き物にする。撫でる・振る・傾ける・叩くといった
触り方に、顔の表情と鳴き声で反応する。

作者自身が持ち歩いて遊ぶためのおもちゃであり、他人に配る製品ではない。

### スコープ

このプロジェクトの成功は「触ったときに生きている感じがするか」の一点で決まる。
反応の質にすべてを注ぐ。

**含むもの**

- IMU による触られ方の検出
- 電源が入っている間だけ連続する短期的な気分
- パラメトリックな顔の描画とアニメーション

**含まないもの（意図的に外す）**

- 電源を切っても残る永続状態。セーブもロードもしない
- 成長・育成・レベル・ステータス
- 歩数計や活動記録
- Wi-Fi、BLE、ネットワーク通信
- 言葉。声は出すが、鳴き声だけで発話はしない
- マイク（Echo Base には付いているが、音に反応する遊びは持たない）
- 地磁気センサ (BMM150) の利用。この遊びには不要

電源投入のたびにペットは同じ初期状態から始まる。これは仕様であって、制限ではない。

### 音

Atomic Echo Base を付けて鳴かせる。AtomS3R 本体にはスピーカーが無い。

言葉は話さない。この顔は口を持たないので、人間的な発話ではなくピッチと
長さで感情を表す鳴き方のほうが噛み合う。

### 電源

開発中は USB 給電を前提とする。バッテリ拡張は後で検討するため、常時全力で描画し
続ける前提の設計は避ける（アイドル時にフレームレートを落とす余地を残す）が、
省電力の作り込みは初期スコープに含めない。

## 2. 入力と反応の対応

| 触られ方 | 検出方法 | 反応 |
|---|---|---|
| 傾ける | 重力ベクトルの向き | 目玉が下方向に転がる。顔全体が少し傾く。常時効いている |
| 撫でる | 小振幅・高周期の加速度、かつ低い角速度 | 機嫌が上がり、やがて目を瞑って笑う |
| 振る | 大振幅の加速度が続く | 瞳が回る。続けると眉を出して怒る |
| 叩く / つつく | 静かな背景に入る単発の鋭い衝撃 | 瞳が開き、短く高く鳴く |
| 持ち上げる | 上向きの加速、または静止から手持ちへの遷移 | はっと目を開けて鳴く |
| 逆さにする | 重力 Y が負 | 困り顔、血が上る |
| 放置 | 一定時間の静止 | だんだん退屈 → うとうと → 寝息 |
| 画面を押す | ボタン | つつくのと同じ扱い。起こす / かまう |

### 「くるくる回す」を外した理由 (2026-09-22)

当初は入れていたが、外した。

AtomS3R にはバッテリが無く USB ケーブルで繋がれたままのため、自由に回せない。
実際に録音したデータでは、Z 軸 (画面法線) 回りの角速度の割合が 0.292 しかなく、
3 軸にほぼ均等に散っていた。回すというより転がす動きになっている。

回転の一貫性 (角速度ベクトルの平均の大きさ ÷ 角速度の大きさの平均) も 0.119 で、
歩行の 0.337 より低かった。つまり録れたデータは回転として成立していない。

バッテリ拡張を入れれば録り直せる。それまでこの反応は持たない。

「傾ける」は他のイベントと排他ではなく、常に姿勢として効き続ける。
残りは離散的なイベントとして発火する。

当初は「逆さ = 重力 Z が負」としていたが、それは画面が下を向いた状態で、
顔が見えない。反応させたいのは画面が見えたまま上下が反転している状態なので、
重力 Y で判定する。画面が真下を向く状態は `faceDown` として別に扱う。

### 気分の連続性

永続状態は持たないが、**電源が入っている間、気分は連続している**。
振られ続ければ怒りが溜まり、撫でれば落ち着く。この短期的な慣性が、
永続状態なしでも手応えを生む中心的な仕掛けである。

## 3. 顔のデザイン (2026-09-22 決定)

実機で 5 案を見比べ、そのうえで参考画像をもとに作り直した。採用しなかった
案のコードは残していない。

### 造作

- ほぼ白の背景に、**淡いグレーの角丸の長方形**の頭。幅 124 × 高さ 86 の
  横長で、四隅の丸みが見える位置に収める
- 頭は一色。顔パッチも耳も持たない
- 目は三層。**白目 → 濃紺の虹彩 → 虹彩の下に覗く水色の三日月**
- 白いハイライトを大小 2 つ。生気のほとんどはこれで決まる
- 目と目の間に**小さな横長のグレーの鼻**。目の中心線より少し下
- **口は持たない**

水色の三日月は、水色で塗ってから濃紺の円を少し上にずらして重ねることで作る。

視線は虹彩が白目の中を動く。虹彩が白目をほぼ埋める構成なので可動量は狭く、
±4px に収まる。

**瞳の大きさは覚醒度で変わる**。興奮すると開き、落ち着くと縮む。生き物は
感情が昂ると瞳孔が開くので、その代わりになっている。

### 口を持たないことの帰結

感情はすべて **目と眉** で表す。

| 感情 | 表し方 |
|---|---|
| 笑い | 目を瞑り、閉じた目を**上向きの弧** `∩` にする |
| 怒り | **眉**を出し、内側を下げる |
| 困り | 眉を出し、内側を上げる |
| 眠い | 目を細め、閉じた目を**下向きの弧** `∪` にする |
| めまい | 瞳孔の動きで表す |

まばたきと笑いはどちらも目を閉じるが、**弧の向きが逆**なので区別がつく。
まばたきはほぼ水平、笑いは `∩`、眠気は深い `∪`。

眉は素の顔には無く、怒りと困りのときだけ現れる。普段が無眉なので、
出たときの印象が強くなる。

これを表すため `FaceParams` に `eyeArch` と `browAngle` を持たせた。

気分が競合したときは**強い感情が勝つ**。めまい > 怒り > 眠気 > 笑い の順で、
閾値を超えたものが顔を占領する。複数を混ぜると何を感じているのか読み取れ
なくなるため。閾値をまたぐ瞬間に顔が飛ばないよう、目と眉は 0.15 秒かけて
補間する。

## 4. 鳴き声

言葉は話さない。ピッチと長さだけで感情を表す。

| きっかけ | 鳴き方 |
|---|---|
| つつかれる | 短く高い「ピッ」 |
| 持ち上げられる | 上がる「ピュイ？」 |
| 機嫌が良くなる | 柔らかく上がる「クルル」 |
| めまい | 音程が揺れる |
| 怒り | 低く濁った音 |
| 眠くなる | ゆっくり下がる |
| 眠っている | ときどき寝息 |

**感情の強さが音量に出る**。怒り 0.5 と 1.0 が同じ音で鳴ると、どれだけ
怒っているのか伝わらない。弱い感情でも消え入らないよう下限は残す。

### 鳴きすぎないこと

これも設計の一部。**気分が変わった節目**と、つつき・持ち上げのときに鳴く。
同じ気分が続くあいだも間を置いて繰り返すが、鳴りっぱなしにはしない。

| 気分 | 繰り返す間隔 |
|---|---|
| めまい | 2.5 秒 |
| 怒り | 3.5 秒 |
| 機嫌が良い | 4.5 秒 |
| 眠い（寝息） | 7 秒 |

平静なときは黙っている。何もされていないのに鳴くとうるさい。
中立に戻る遷移でも鳴かない。

### 音色

`tone()` の矩形波はブザーに聞こえる。波形を自前で合成して PCM で流す。
生き物の声に近づけるために次の 4 つを入れている。

1. 正弦波に倍音を少し混ぜる（純粋な正弦は柔らかすぎて芯がない）
2. 音符の変わり目をポルタメントで繋ぐ（段差が機械的に聞こえる）
3. 立ち上がりと立ち下がりに傾きを付ける（急に切れるとプチッと鳴る）
4. わずかなビブラート（一定のピッチは無機質に聞こえる）

位相は音符をまたいで連続させる。途切れさせるとそこで必ず雑音が出る。

## 5. アーキテクチャ

ハードに触る層と、触らない純粋ロジック層を完全に分離する。

おもちゃの面白さの大部分は「撫でるを撫でると判定する閾値」と「気分の遷移カーブ」の
チューニングで決まる。そこを実機への書き込みなしで反復できるかが開発速度を決める。

```
[I/O]  ImuSource       M5.Imu → ImuSample{ax,ay,az,gx,gy,gz,t}
          ↓
[純粋] MotionAnalyzer  ImuSample の列 → Posture + MotionEvent + Activity
          ↓
[純粋] Mood            出来事と状態 + 経過時間 → MoodState
          ↓
       ├→ [純粋] FaceComposer  MoodState + Posture → FaceParams
       │      ↓
       │  [I/O]  FaceRenderer  FaceParams → M5GFX 描画
       │
       └→ [純粋] VoiceComposer MoodState + 出来事 → VoiceCue (音符の並び)
              ↓
          [純粋] VoiceSynth    VoiceCue → PCM
              ↓
          [I/O]  VoiceOutput   PCM → M5.Speaker
```

### 各ユニットの責務

**ImuSource** (I/O)
M5Unified の `M5.Imu` から加速度・ジャイロを読み、タイムスタンプ付きの
`ImuSample` を返す。軸の向きの補正もここで吸収し、以降の層には
「画面に対して素直な座標系」だけを見せる。

**MotionAnalyzer** (純粋)
`ImuSample` の列を受け取り、2 種類の出力を出す。

- `Posture` — 連続量。重力ベクトルから得た傾き、上下の向き
- `MotionEvent` — 瞬間的な出来事。つつき・持ち上げ
- `Activity` — 継続している状態。静止・撫で・手持ち・振り

`Activity::Held`（手に持たれている）は「動いているが撫でられてはいない」
ことを表す受け皿。撫でと線形加速度が重なるため、これが無いと手に持っている
だけで撫でと判定される。分離は角速度で行う。

M5 のヘッダを include しない。

**Mood** (純粋)
`MotionEvent` の列と経過時間から `MoodState` を更新する。

- `arousal` — 覚醒度。放置で下がり、刺激で上がる
- `valence` — 機嫌の良し悪し
- `dizziness` — めまい。振られると溜まり、時間で抜ける
- `anger` — 怒り。乱暴に扱われ続けると溜まる
- `sleepiness` — 眠気。静止時間で上がる

各値は時間減衰する連続量として持つ。状態機械ではなくパラメータの集合とすることで、
表情の中間表現が自然に出る。

**FaceComposer** (純粋)
`MoodState` と `Posture` から `FaceParams` を組み立てる。
視線の位置・目の開き具合・閉じた目の弧・眉の角度・顔の傾き。

顔はドット絵スプライトではなく、パラメータで動かす。スプライトを何十枚も描かずに、
傾きに連動した滑らかな中間表現が出せるため。

**FaceRenderer** (I/O)
`FaceParams` を M5GFX で描く。`M5Canvas` に 128×128 を丸ごと描いてから
一括転送し、ちらつきを消す。顔は水平な状態で描いてから回転させて合成する。
座標だけ回す実装では目や口の「形」が傾かないため。

**VoiceComposer** (純粋)
気分と出来事から `VoiceCue`（音符の並びと強さ）を作る。鳴くかどうかの
判断もここ。音は鳴らさない。

**VoiceSynth** (純粋)
`VoiceCue` を PCM の波形に変える。ここも M5 に依存しないのでテストできる。

**VoiceOutput** (I/O)
合成した PCM を `M5.Speaker.playRaw()` で流す。

### 動作レート

- センサ読み取り: 約 100Hz
- 描画: 30fps

## 6. テスト戦略

PlatformIO の `env:native` を用意し、純粋層 (`MotionAnalyzer` / `Mood` /
`FaceComposer`) を Mac 上で直接コンパイル・テストする。

### モーションフィクスチャ

デバッグビルドで IMU の生データをシリアルへ CSV 出力する経路を用意する。
実際に「撫でる」「振る」「叩く」「ポケットに入れて歩く」を実機で録り、
`test/fixtures/*.csv` に保存する。

以降のテストは、この実データを `MotionAnalyzer` に流し込んで期待するイベントが
出るかを検証する。これにより「撫でたのに叩いたと誤判定する」種の問題を、
実機への書き込みなしで再現・修正できる。

誤判定を見つけるたびにフィクスチャが増え、閾値のチューニングで過去の挙動が
壊れないことが保証される。この仕組みの有無が、この種のプロジェクトの完成度を
決定的に左右する。

`FaceComposer` は入力から出力パラメータへの純粋関数なので、代表的な
`MoodState` に対する `FaceParams` を検証する。描画そのものは目視で確認する。

## 7. 実装の順番

1. **顔が出て、傾けると目玉が転がる**
   `ImuSource` → `Posture` → `FaceComposer` → `FaceRenderer` の縦の串を通す。
   ここまででおもちゃとして既に成立する
2. **叩く・振る・撫でるの検出**
   同時に CSV 出力とフィクスチャ基盤も作る
3. **気分の慣性と表情遷移**
   `Mood` を入れ、反応が連続的になる
4. **放置 → うとうと → 寝息、細かい演出**

## 8. 実機確認の結果 (2026-09-22)

フェーズ 0 で実機確認済み。

### 確定した事項

| 項目 | 結果 |
|---|---|
| IMU | **BMI270**。M5Unified 0.2.7 が認識する。専用ドライバは不要 |
| PSRAM | **8MB 有効** (8,386,231 bytes)。`memory_type = qio_opi` で正しく効く |
| Flash | 8MB |
| 画面 | 128 × 128 |
| 加速度の単位 | g。静止時のベクトル長が 1.00 |
| ジャイロの単位 | deg/s。静止時のノイズは ±1 程度 |

### 軸の向き

実測の結果、**IMU の軸は画面座標と素直に揃っている**。

- **+X = 画面の右方向**
- **+Y = 画面の上方向**
- **+Z = 画面の外向き**（手前）

静止時の加速度は「世界の上方向」を機体座標で表したベクトルになる。

実測値（4 姿勢）:

| 姿勢 | ax | ay | az |
|---|---|---|---|
| 画面上・水平 | -0.012 | -0.008 | +0.993 |
| 画面手前・垂直 | -0.003 | +0.998 | +0.026 |
| 垂直から右へ傾ける | -0.748 | +0.661 | +0.013 |
| 逆さ | -0.013 | +0.035 | -1.008 |

3 番目は「垂直姿勢から上端を右へ 48.5 度」と解釈でき、理論値
`(-sin48.5°, cos48.5°) = (-0.749, +0.662)` と小数第 3 位まで一致する。
右手系として矛盾がない。

**したがって `ImuSource` での軸の入れ替えや符号反転は不要。**
描画時に画面のピクセル Y が下向きである分だけ反転すれば済む。

### 未確認のまま残す事項

- **RGB LED の有無**。未確認のまま、今回は使わない方針とする。
  無くても設計は成立し、確認のために未知の GPIO を駆動するリスクを取る
  価値がない。感情表現は画面だけで行う
